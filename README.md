# mangaP2ePub

スキャン済み PDF（紙の本を裁断してドキュメントスキャナで取り込んだ、1 ページ 1 画像の PDF）を、**固定レイアウト（漫画）ePub3** に変換する CLI ツールです。

出力は [EBPAJ 1.1.2](https://github.com/ebpaj/ebpaj-epub3-specs) のコミック仕様に準拠した pre-paginated EPUB3 で、ビューポートは 1103×1600 固定、右綴じ（`page-progression-direction="rtl"`）がデフォルトです。

---

## 特徴

- **PDF から埋め込み JPEG を無劣化で抽出**（1 ページ 1 画像前提）
- 全ページを **1103×1600 にフィット**（アスペクト比維持・白レターボックス）
- cover（表紙）は `page-spread-center`、本文は rtl で奇数=right / 偶数=left に自動割り付け
- TOC は最小 3 項目（**表紙 / 本編 / 奥付**）を `navigation-documents.xhtml` と `toc.ncx` の両方に出力
- ファイル名 `作品名_作者名.pdf` / `作品名-作者名.pdf` から **題名・作者を自動抽出**
- デフォルト出力名は `作品名_作者名.epub`（入力 PDF と同じディレクトリ）
- **ScanSnap 等の誤判定で混入した横長ページを自動で 90° 回転**（既定 ON、表紙・見開き等の本物の横長ページは保持）
- **モノクロ漫画ページを自動でグレースケール化**（色相分析で「紙焼け・セピア地色」と「本物のカラーページ」を判別。表紙は常にカラー維持、冒頭カラーページ・淡色カラー扉も保護）+ JPEG 品質 78 既定で**容量約 25-35% 削減**
- **小説スキャンの上下左右余白を自動クロップ**（既定 ON、漫画は自動スキップ、日焼けセピア紙にも適応）— 同じ viewport 内でテキストが約 20-40% 拡大
- **スキャナー OCR のテキスト層を ePub に埋め込み**（既定 ON、要 pdfminer.six）— PDF 内の透明テキストを文字単位の座標付きで抽出し、各ページの SVG に透明 `<text>` として重ねるため、**全文検索・位置どおりのテキスト選択・コピペ**が可能（Google Play Books / Thorium / calibre で動作確認。Send to Kindle は変換時にテキスト層が失われる）。トーン誤認識などの OCR ゴミ行は自動除去

## 必要環境

- Python 3.10 以上
- [pypdf](https://pypi.org/project/pypdf/)
- [Pillow](https://pypi.org/project/Pillow/)
- [pdfminer.six](https://pypi.org/project/pdfminer.six/)（任意 — OCR テキスト層の埋め込みに必要。未インストール時はテキスト層なしで変換続行）

```bash
pip install pypdf Pillow pdfminer.six
```

## 使い方

### 最小呼び出し（ファイル名から自動取得）

```bash
python3 manga_p2epub.py 長い長いさんぽ_須藤真澄.pdf
```

上記だけで以下を行います：

- `長い長いさんぽ` を題名、`須藤真澄` を作者として抽出
- 同じディレクトリに `長い長いさんぽ_須藤真澄.epub` を生成

### オプションで上書き

```bash
python3 manga_p2epub.py scan.pdf \
    --title "作品名" \
    --author "著者名" \
    -o /path/to/output.epub \
    --force
```

### 全オプション

| オプション | 既定値 | 説明 |
|---|---|---|
| `pdf` (位置引数) | — | 入力 PDF（必須） |
| `-o`, `--output` | `<title>_<author>.epub` | 出力 EPUB パス |
| `--title` | ファイル名から抽出 | 題名を明示指定（ファイル名優先解決を上書き） |
| `--author` | ファイル名から抽出 | 作者（原作）を明示指定。`dc:creator` role=aut |
| `--artist` | なし | 作画（絵）。2人目の `dc:creator` を role=art で追加。原作と作画が別の作品向け |
| `--publisher` | なし | 原出版社。`dc:publisher` に記録し、yomikake ビューアの書誌ブロック「出版社」欄に表示 |
| `--isbn` | なし | 底本の ISBN。`dc:source`（`urn:isbn:…`）に記録し、yomikake が国立国会図書館サーチ等の書誌検索リンクに使う（ハイフン可・自動除去） |
| `--date` | なし | 原刊行日。`dc:date` に記録（例 `2016-03-03`） |
| `--direction` | `rtl` | ページ送り方向（`rtl` または `ltr`） |
| `--quality` | `78` | JPEG 品質（1–95）。上げれば高品質・大容量、下げれば軽量化 |
| `--no-auto-rotate` | オフ | 横長ページの自動回転を無効化（既定では有効） |
| `--no-auto-crop` | オフ | 余白の自動クロップを無効化（既定では有効） |
| `--no-text` | オフ | OCR テキスト層の埋め込みを無効化（既定では有効） |
| `--force` | オフ | 出力先が存在しても上書き |

## ファイル名からのメタデータ抽出ルール

入力 PDF の拡張子を除いたファイル名（stem）に対して、以下の順で区切り文字を探します：

1. アンダースコア `_`（優先）
2. ハイフン `-`（フォールバック）

最初に見つかった**1 回分**で分割し、前半を題名、後半を作者とします（`partition` 方式）。そのため題名や作者に区切り文字以外の `-` を含んでいても途中で壊れません。

| ファイル名 | 題名 | 作者 |
|---|---|---|
| `長い長いさんぽ_須藤真澄.pdf` | 長い長いさんぽ | 須藤真澄 |
| `作品名-作者名.pdf` | 作品名 | 作者名 |
| `A-B_C.pdf` | A-B | C |
| `no_separator.pdf` | no | separator |
| `タイトルのみ.pdf` | タイトルのみ | （なし → `unknown`） |

`--title` / `--author` を指定した場合は常にそちらが優先されます。

## 出力 EPUB の構造

```
mimetype                              (STORED、先頭固定)
META-INF/container.xml
item/standard.opf                     (EPUB3 OPF、EBPAJ 1.1.2 準拠)
item/navigation-documents.xhtml       (EPUB3 nav)
item/toc.ncx                          (EPUB2 互換 NCX)
item/style/fixed-layout-jp.css
item/xhtml/p-cover.xhtml              (表紙ページ SVG wrapper)
item/xhtml/p-001.xhtml
…
item/xhtml/p-NNN.xhtml
item/image/cover.jpg                  (1103×1600 に正規化)
item/image/i-001.jpg
…
item/image/i-NNN.jpg
```

各ページの XHTML は、SVG で画像 1 枚をビューポートに貼っただけの最小構造です：

```xml
<svg xmlns="http://www.w3.org/2000/svg" xmlns:xlink="http://www.w3.org/1999/xlink"
     version="1.1" width="100%" height="100%" viewBox="0 0 1103 1600">
  <image width="1103" height="1600" xlink:href="../image/i-001.jpg"/>
</svg>
```

### spine の配置ルール

- 1 ページ目（cover）: `rendition:page-spread-center`
- 2 ページ目以降（`rtl` 時）: 奇数番目 → `page-spread-right`、偶数番目 → `page-spread-left`
- `ltr` 指定時は左右が反転

### TOC の 3 項目

| ラベル | リンク先 |
|---|---|
| 表紙 | `xhtml/p-cover.xhtml` |
| 本編 | `xhtml/p-001.xhtml` |
| 奥付 | `xhtml/p-<最終ページ番号>.xhtml` |

`navigation-documents.xhtml` と `toc.ncx` の両方に同じエントリが入ります。2 ページ以下の PDF では項目数が自動的に減ります。

## 横長ページの自動回転（既定 ON）

ScanSnap などのドキュメントスキャナは、縦組み本のページの一部を「横組み」と誤認識して 90° 回転した状態で PDF に保存することがあります。本ツールは縦長優勢の PDF にそのような横長ページが混入している場合、自動で縦長に回転して EPUB に出力します。

### 検出と判定

1. **プリスキャン** — 全ページの画像寸法を取得し、縦長ページの中央値 (pw_med, ph_med) を算出。
2. **誤スキャン候補の判定** — 横長ページのうち寸法が `(ph_med, pw_med)` に ±10% で一致するものだけを回転対象とする。これにより、表紙や見開き（縦長中央値より明らかに大きい横長）は据え置かれる。
3. **回転方向の自動判定** — 冒頭の標準縦長ページ（先頭2ページは表紙・扉として除外、最大5枚）から上下端 10% バンドの平均輝度を測り、書籍ごとの「天地どちらが明るい（=余白が広い）か」を学習。横長ページの左右端輝度を同じバンドで測り、明るい側が原寸の上端だった方向に CW / CCW を決める。
4. **判定不能時** — 左右輝度差が小さい場合は CW で既定回転（誤判定はビューア側での回転で対応可能との前提）。

### 制限

- 縦長ページ比率が 50% 以下の PDF（横長本）では機能を自動 OFF。
- 候補ページが 0 枚なら何もしない。
- 無効化したい場合は `--no-auto-rotate` を指定。

## ページ余白の自動クロップ（既定 ON）

スキャンした小説等で生じるページ周囲の白余白を削り、ビューポート 1103×1600 内に本文がより大きく表示されるようにします。書籍単位で **1 つの一律クロップ矩形**を決定し、全ページに同じ比率で適用するため、ビューワで読んだときテキスト位置が安定します。

### 検出と判定

1. PDF 中央 90% から **10 ページを均等サンプリング**（前後 5% は表紙・奥付として除外）。
2. 各サンプル：
   - 4 隅の輝度中央値から `paper_color` を推定（日焼け／セピア紙にも追従）。
   - `threshold = max(180, paper_color − 25)` で適応的二値化。3px median filter で事前デノイズ。
   - 上下左右ともに「行/列の暗ピクセル比 ≥ 1%」が現れた最初の位置を content 端とし、ページ寸法に対する**比率**で記録（混在解像度 PDF 対応）。
3. 外れ値除外：いずれかの辺が >30%（章末や全面イラスト）、または 4 辺合計 <1%（黒地ページ）のサンプルを除外。
4. 残りサンプルが 3 件未満ならクロップ無効。
5. 各辺の **25 percentile** を採用。

### 漫画自動スキップ（書籍単位）

**4 辺すべてが ≥ 3% である場合のみクロップ有効**。漫画はコマ割りが端まで延びている辺が多いため自動的にスキップされます。逆に 4 辺余白を持つ書籍（典型的な小説、4 コマ漫画など）は対象になります。

### 挿絵ページ自動保護（ページ単位）

書籍単位でクロップが有効になった場合でも、各ページごとに以下のチェックで**カラー表紙・冒頭カラー挿絵・文中全面挿絵**だけはクロップを skip し、原寸（letterbox）で出力します。

- **ページがカラーコンテンツを含む** → クロップ skip（表紙、カラー挿絵）
- **ページ自身の 4 辺のうち 2 辺以上が < 3% margin** → クロップ skip（モノクロ全面挿絵）
- 1 辺だけ 0% は章末ページ等のページ番号・端アーチファクトと見做して通常クロップ

書籍末尾には `[auto-crop] applied to N page(s); preserved C color and B full-bleed illustration page(s)` のサマリが出力されます。

### 適用順序

横長補正回転 → **自動クロップ** → 1103×1600 ビューポート正規化。

### 注意

- ビューポート内にテキストが大きく表示される一方、JPEG 内のコンテンツ密度が上がるため**ファイルサイズは数 % 増えることがあります**。容量優先なら `--no-auto-crop` で無効化可能。
- 小さいページ番号や柱は端に寄せられている場合、検出端より外側にあれば一緒にクロップされます。

## 画像正規化の仕様

- すべて **1103×1600** にアスペクト比維持でフィット
- 余白は白（RGB は `(255,255,255)`、グレースケールは `255`）で埋める
- モードは `L`（グレースケール）か `RGB`。それ以外（CMYK, P など）は `RGB` に変換
- **RGB 画像のうちモノクロ印刷ページは自動的に L mode に変換**（後述）
- JPEG 品質 78 既定（`--quality` で変更可）、`optimize=True`
- 既に 1103×1600 の画像もエンコーダ挙動を揃えるため再エンコードします

### グレースケール自動検出（色相ベース）

スキャンされたモノクロ本は紙の地色（セピア・黄ばみ＝紙焼け）の影響で RGB のまま保存されているケースが多く、そのままだとファイルサイズが嵩みます。一方で「淡い色の表紙」「単色刷りの扉」「フルカラー漫画ページ」を誤ってグレースケール化してはいけません。本ツールは**紙焼けは物理的に必ず黄〜橙の暖色**という性質を利用し、ページごとに以下を判定します。

1. **彩度のある画素（max(R,G,B) − min(R,G,B) > 30）が 1% 未満** → 純粋な白黒スキャンとして L mode に変換。
2. それ以外は、彩度のある画素の**色相ヒストグラム**（HSV）を分析。以下を**すべて**満たす場合だけ「モノクロ印刷 + 紙焼け」としてグレースケール化：
   - 色相の集中度が高い（単一色相 ≥ 0.90。実測：紙焼け ≥ 0.99、フルカラー 0.1〜0.85）
   - 色相が暖色域 20〜75°（黄〜橙）に集中
   - 平均彩度 ≤ 65（実測：紙焼け紙 42〜55、鮮やかな色刷り ≥ 72）
3. どれか外れたら**カラーページとして RGB 維持**（青系の淡い表紙、ピンク・緑の単色刷り、フルカラーページなど）。

さらにページ単体の判定を補う書籍単位のルールが 2 つあります：

- **表紙（1 ページ目）は無条件でカラー維持**（橙一色のカラー表紙は原理的に紙焼けと区別できないため）
- **サンドイッチ補正** — カラーページに挟まれた 2 ページ以下のグレー判定は、カラーページの誤判定と見做してカラーに反転（カラー口絵は連続ブロックで印刷されるため）

変換ログには `[color-detect] N/M page(s) kept in color` としてカラー維持ページ数が表示されます。新オプションは追加していません（必要なら `--quality` で品質を上下できます）。

## OCR テキスト層の埋め込み（既定 ON）

ドキュメントスキャナ（ScanSnap 等）が生成する PDF には、OCR 結果が透明テキストとして埋め込まれており、PDF リーダーでの検索やコピペに使われています。本ツールはこのテキストを **pdfminer.six** で文字単位の座標付きで抽出し、各ページ XHTML の SVG 内に透明の `<text>` 要素（`fill-opacity="0"`、グリフごとの x/y 座標リスト）として画像の上に重ねます。

- **検索・テキスト選択・コピペが可能** — 透明テキストは画像上の文字位置と一致するため、選択ハイライトが原文の文字に重なります。縦書き段組は右から左の正しい読み順で格納
- 電書連（旧電書協）固定レイアウトガイドの公式テンプレートが使う「SVG 内の透明オーバーレイ要素」（リンク領域 `<a><rect fill-opacity="0.0"/></a>`）と同じ構造のため、ガイド準拠のまま
- **動作確認済みリーダー**: Google Play Books（検索・選択・コピー）、Thorium、calibre。**Send to Kindle は変換過程でテキスト層が失われるため非対応**
- ファイルサイズへの影響は小説 1 冊で数百 KB 程度

### OCR ゴミ行の自動除去

漫画ページではスクリーントーンや描線を文字と誤認識したゴミ（「■■」「�」、ランダムな漢字など）が OCR 層に大量に含まれます。以下の 2 段フィルタで除去します：

1. **良文字率フィルタ** — 行の文字のうち かな・漢字・英数・句読点 の比率が 70% 未満の行を破棄（半角カナは縦書き書籍に現れないためゴミ扱い）
2. **1 文字行フィルタ** — 英数字（ノンブル）以外の 1 文字だけの行を破棄（実本文の縦 1 段は数十文字あるため）

実測では小説（RAIL WARS!）で本文の誤除去ゼロ、漫画（AKIRA）でゴミの大半を除去できますが、**ランダムな漢字に化けたトーンノイズは原理的に文字種では区別できず一部残ります**（不可視のため実害は検索ノイズ程度）。漫画で気になる場合は `--no-text` で無効化してください。

### 制限

- `/Rotate` 指定ページと自動回転（誤スキャン補正）されたページは、OCR 座標が画像と一致しなくなるためテキスト層をスキップします
- ルビ（振り仮名）も独立した行として埋め込まれるため、範囲コピーにルビ文字列が混ざることがあります

## スコープと制限（v0.2）

- **対象は漫画（固定レイアウト）専用**。小説・リフロー EPUB は対象外
- 1 ページに画像が**ちょうど 1 つ**埋め込まれている PDF を想定（多くのドキュメントスキャナ出力がこれに該当）
- 1 ページに画像が複数ある場合は**先頭の画像のみ**採用し警告を出す
- 画像を持たないベクター PDF は現状サポート外（将来 PyMuPDF でラスタライズ対応予定）
- OCR テキスト層は PDF に埋め込み済みのものを転記するだけで、OCR 自体は行わない（テキストなし PDF はテキスト層なしで変換）
- 傾き補正は未実装
- [epubcheck](https://github.com/w3c/epubcheck) による自動検証は未実装
